# 给 Gemini 的提示词（直接复制粘贴）

> 用法：把对应的 JSON 文件拖进 Gemini 对话窗口（不是贴路径），然后把下面这段提示词一起发出去。
> 分卷文件：`brief-batch-1-events.json`（事件卡，64 KB）、`brief-batch-2-chains.json`（思维链，202 KB）、`brief-batch-3-pools-approaches.json`（通用句 + 解法，89 KB）。
> 建议一次只发一卷；202 KB 那卷如果 Gemini 说太长，就说「先只处理前 30 个 item，保持 key 和结构，输出 JSON」。

---

## 提示词正文

```
你是这个中文网页游戏《OI 模拟赛 · 校赛版》的文案写手。我上传的是一个 JSON 写作任务包，里面：

- meta：项目背景、文风要求、写作红线、字数上限
- batches[].items[]：每一条要改写的文字，字段含义：
  - key：唯一标识（不要改）
  - location：在代码里的位置（不要改）
  - when：这句话出现在游戏界面的什么位置、什么时机
  - limit：字数上限（中文按字符数算，超了会截断或撑破布局）
  - current：当前文字（你要改写的对象）
  - issue：当前文字的问题
  - hint：改写方向

任务：改写每个 item 的 current 文字，然后按**完全相同的 JSON 结构和 key** 输出。

硬性要求：
1. 只改字符串内容，不改 key、字段名、结构、顺序；不删 item。
2. 不写解释、不写前言后语，直接输出 JSON（放在一个 ```json 代码块里）。
3. 严格遵守 limit；中文标点算 1 个字。
4. 文风：选手心里的短句 / 教练视角的叙述；具体、克制、允许自嘲；不煽情；不用「你」「玩家」「让我们一起」；不用 emoji。
5. 术语必须准确（CSP-S、NOIP、省选、WC、APIO、NOI、CTT/CTS、挂分、卡常、对拍、省一、国集、D 类、freopen）。
6. 每条都要有具体信息（数字、复杂度、动作、场景），不要写成通用建议。
7. 事件卡新增条目（若我要求扩写）：照现有字段补全，id 用英文小写下划线，效果数值不要编，用 effectHint 写一句自然语言描述。
8. quotes.json 里的选手语录是真人原话，禁止改写（它不在这个任务包里）。

自检清单（输出前逐条过一遍）：
- 每个 current 都换成了新句子，没有漏 item
- 没有一句超过 limit
- 没有出现「让我们一起」「在这个旅程中」「值得注意的是」这类 AI 腔
- 三条事件选项的代价方向彼此不同
- 生成的 JSON 能通过 JSON.parse（不要有尾逗号、注释、单引号）

如果你认为某句已经足够好，可以只做微调，但不要留空、不要返回 null。
```

## 更省事的说法（如果他嫌上面太长）

```
这是一个网页游戏的文案任务包 JSON。请你改写 items 里每一条的 current 字段，
严格遵守 limit 字数上限和 meta.style 里的文风要求，不要改 key 和结构，
不要改动 quotes（真人原话）。直接输出同结构 JSON，不要解释。
另外：每条要有具体细节（复杂度、动作、场景），避免 AI 腔。
```
