## 二、逐题拆链

### P17827（d1）：两步，没有算法

> 「读题发现没有问左右关系。因此，可以把所有的 D 换成 G。」

链：**读题 → 发现自由度（左右关系无关）→ 映射到字符距离 → 四个子问题各一行判断**。

全文 30 行，代码 20 行。没有任何数据结构、没有任何复杂度讨论。**难点在「读懂题面 + 想到可以改字母」**，一旦想到就结束。

### P17831（d2）：一条性质 + 一个套路

> 「观察到本题有如下性质：……存在一个最优解，其参与合成的水晶在排序后是连续的一段。」

链：**排序 → 猜「最优解是连续段」→ 证明（换中间元素不劣）→ 前缀和算代价 → 发现单调性 → 双指针**。

关键句都是「不难证明」「显然」。复杂度 O(n log n)，瓶颈在排序。代码 25 行。

### P17832（d4）：先有模型，再有瓶颈，最后一步技巧

> 「原解法时间复杂度 O(n∑kᵢ + n³ + qn²)。查询部分需要 O(qn²)，因此考虑优化查询。」

链：**建图（站点↔线路）→ 最短路 → 写出暴力式 → 找瓶颈（枚举 u,v）→ 用「最短路子路径仍是最短路」拆开 → 预处理 s_{v→y} → 离线按 y 算**。

O(n∑kᵢ + n³ + qn)。d4 的分水岭：**不是不知道怎么做，而是知道怎么做之后还要再优化一层**。

### P17833（d7）：没有现成算法，全靠自己造

> 「我感觉我的做法挺人类的，不过我不清楚这算是什么算法……不确定是不是假解，欢迎 hack。」

链：**画图建模 → 发现「终点只能落在最远/次远/第三远」→ 把方案拆成左右两段独立计数 → 处理「不可取」的边界（左右跳的最远点）→ 递推 pre/suf → 乘积求和**。

题主自述「开考 180 分钟完成」，代码 60 行，全文一半在解释「为什么这样分类」。

**d7 的典型形态：没有模板可套，链条是「试 → 观察 → 收缩」的搜索过程，而不是一条直线。**

### P17834（d8）：五级转化，每级都可能断

> 「二分答案 r。记录剥 r 轮叶子后剩下的点集为 C_r。」
> 「只需在 C_r 内选：因为 C_r 外的挂在 C_r 的叶子上不劣。」
> 「因此不选的点只能是度数为 2 的点，并且必须形成一条连续路径。」
> 「每个点会禁止一段『删除区间起点』的取值，用差分数组覆盖所有禁止区间。」

链：**二分答案 → 剥叶子分层 (tim) → 转化为「在 C_r 里删 L 个点」→ 度数分类（叶子必选、度数≥3 必选）→ 只剩二度链 → 链上连续删区间 → 每个点转成一段被禁止的起点 → 差分判存在**。

O(n log n)。这一段里有 **5 次等价转化**，任何一步想不到就卡死；而代码只有 70 行——**难度与代码量完全脱钩**。

### P14637（d8，NOIP）：先设计状态，再优化转移

> 「先将 mex 转化为到根结点链上的最长传递链的长度……注意到如果一条链太短了，对答案没有贡献，这条链一定是不优的。」

链：**mex → 最长传递链 → 设计 f/g 两套 DP 状态 → 写出 O(nm²) 暴力 → 发现需要「路径和」→ 树状数组太麻烦 → 换成带权并查集 → O(nm)**。

这篇是「别人都写树状数组，我换个数据结构」——**同一道题的思维链可以有多条**，题解区 12 条评论里一半在感叹这一点。

## 四、难题与简单题的六条差别

1. **链长不同，且不是线性增长。** d1–d2 是「一步转化 + 实现」；d4 起变成「模型 → 暴力 → 瓶颈 → 优化」；d7–d8 是 4–6 级转化，每级都要自证正确。
2. **简单题的难度在「想到」，难题的难度在「想到之后还要再想到」。** T1 都是看一眼就会，T4 是「会了第一步才知道第二步存在」——链条是**串行依赖**的，前一步想不到，后面全部不可见。
3. **难题的思维链是搜索过程，不是直线。** d7 那位作者写「我不清楚这算是什么算法」「不确定是不是假解」；d8 作者写「只需……因为……因此……」——**真实的高难题解里含有大量「先试错再收缩」的痕迹**，而不是一条完美推导。
4. **复杂度是硬门槛。** d2 瓶颈在排序都算过关；d4 必须从 O(qn²) 降到 O(qn)；d7 要 O(n)；d8 要 O(n log n)。**每升一档，要求的复杂度级别就抬一级**，这比「代码难写」更能区分难度。
5. **代码量与难度脱钩。** 6 道题代码 20–80 行，但 d1 到 d8 的思维跨度是几十倍。**用「写多少行」来表现难度是错的，应该用「几次转化」。**
6. **高难题一题多解，且解法风格差异大。** 同一道 T4 有人二分+剥叶子，有人换别的角度；NOIP T3 有人树状数组、有人带权并查集。**「同一道题多个思维链」在现实中是常态，不是游戏需要发明的设定。**

补充一个社区观察：d2 题解区的热评是「这才是 CSP 啊」「虽然看不懂，但应该很 NB」——**高难题的观赏性来自「看不懂但知道很难」，而不是来自文字优美**。

## 五、对游戏「思维链」设计的直接启示

1. **链条粒度按难度分档，不要统一 5 步。**
   - d1–d2：2–3 步（读题 → 关键观察 → 写）；
   - d3–d5：4 步（建模 → 暴力 → 瓶颈 → 优化）；
   - d6–d8：5–6 步，且每步必须能独立「断」。

2. **断点与得分对齐的方式，照抄真实题解的「分层」：**
   - 写出暴力 → 10/22 分；
   - 想到正确模型但优化不掉 → 40/60 分；
   - 想到全部转化但边界漏 → 80–90 分；
   - 全链走通 → 100 分。
   这正好对应洛谷题解里「先写 O(nm²) 拿部分分，再优化」的真实路径。

3. **「走偏」要写成真实人类会走的路。** 从样本里能直接借用的偏路：
   - 「以为这题是 DP，其实是图论」（T3 作者自述不清楚算什么算法）；
   - 「想到树状数组，但嫌麻烦换了个结构」（NOIP T3）；
   - 「复杂度算错，以为 O(n²) 能过」（评论区常见）。
   每条偏路都应对应一个明确的分段损失（掉 20–40 分），而不是「随便写错」。

4. **用真实题解的语感做词库。** 高频措辞：`观察到`、`不难证明`、`注意到`、`因此考虑优化`、`只需在……内选`、`感觉挺人类的`、`不确定是不是假解`。这些词比生造的「他陷入了沉思」更像 OI 选手。

5. **一题多链是必须的。** 现实里 d8 题有 2–3 种主流做法，游戏里每道难题准备 2 条 canonical + 1 条 trap 链，成本不高但真实感提升明显。

6. **简单题的链要「短而致命」。** d1 这种题，链只有两步，断点只能是「读错题」——这反而是很好的新手教学：让玩家看到「他没改 D 为 G，所以四个判断全错」。

## 六、可直接进 `src/thinking.ts` 的链样本

```ts
// d8 型（P17834 抽象）
canonical: [
  { kind:'observe', text:'答案有单调性，可以二分' },
  { kind:'transform', text:'剥 r 轮叶子，剩下的点集 C_r 里还要少选 L 个' },
  { kind:'observe', text:'C_r 外的点挂在 C_r 叶子上，选了不劣 → 只需在 C_r 内选' },
  { kind:'structure', text:'叶子必选、度数≥3 必选，只有二度点能删且必须连成一段' },
  { kind:'optimize', text:'二度链上删长度为 L 的区间 → 每个点禁止一段起点 → 差分' },
],
traps: [
  { text:'以为要 DP 树形背包', loss: 40 },
  { text:'漏掉「度数≥3 必选」导致连通块被割开', loss: 30 },
]

// d1 型（P17827 抽象）
canonical: [
  { kind:'observe', text:'题目不问左右，所以 D 可以当成 G' },
  { kind:'corner', text:'四个子问题只差「车厢/排号/座位距离」三个条件' },
]
```
